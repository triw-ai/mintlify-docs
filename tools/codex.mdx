---
title: "Codex CLI"
description: "Register Triw as an OpenAI-compatible model provider in Codex."
---

Codex reads model providers from `~/.codex/config.toml`. Triw is a normal OpenAI-compatible provider, so this is a four-line block.

## Configure

```toml ~/.codex/config.toml
model = "gpt-5-codex"
model_provider = "triw"

[model_providers.triw]
name = "Triw"
base_url = "https://router.triw.io/v1"
env_key = "TRIW_API_KEY"
```

```bash
export TRIW_API_KEY="sk-..."
codex
```

`env_key` names the environment variable Codex reads at runtime — the key never lands in the config file.

## Choosing a model

Set `model` to an id your key can see:

```bash
curl https://router.triw.io/v1/models -H "Authorization: Bearer $TRIW_API_KEY"
```

Coding-oriented ids are usually the `codex`, `gpt-5*` or `claude-*` families, depending on what the operator has connected.

## Verify

```bash
codex --version
codex "reply with the word ready and nothing else"
```

Expected: a single word. Then check the console log page — the request should appear with your key and the model you set.

## Gotchas

- `base_url` must end in `/v1`. Codex appends `/responses` or `/chat/completions` itself.
- If you keep multiple providers, remember `model_provider` is what selects one; editing the block alone changes nothing.
- On Windows, config lives at `%USERPROFILE%\.codex\config.toml`.
