OpenClaw is a Node-based agent gateway with its own provider catalog. Custom endpoints are declared under `models.providers`.

## Requirements

| Item | Minimum |
| --- | --- |
| Node | 24.16+ on 24.x, or 26.1+ (26 recommended) |
| OS | macOS, Linux, Windows (WSL recommended) |
| Network | outbound HTTPS to `router.triw.io` |

## Install

```bash
curl -fsSL --proto '=https' --tlsv1.2 https://openclaw.ai/install.sh | bash
openclaw --version
```

The installer provisions Node when the host has none. Windows: use the PowerShell installer from [docs.openclaw.ai/install](https://docs.openclaw.ai/install).

## Configure

Declare Triw as an OpenAI-completions provider, then point the default agent model at it:

```json5 ~/.openclaw/config.json5
{
  agents: {
    defaults: { model: { primary: "triw/claude-sonnet-4-5" } }
  },
  models: {
    providers: {
      triw: {
        baseUrl: "https://router.triw.io/v1",
        api: "openai-completions",
        apiKey: "${TRIW_API_KEY}",
        models: [
          { id: "claude-sonnet-4-5", name: "Claude Sonnet 4.5" },
          { id: "gpt-4o-mini", name: "GPT-4o mini" }
        ]
      }
    }
  }
}
```

```bash
export TRIW_API_KEY="sk-..."
```

You can also run onboarding and choose the custom-provider path:

```bash
openclaw onboard --custom-base-url https://router.triw.io/v1 --custom-model-id claude-sonnet-4-5
```

## Verify

```bash
openclaw models list          # triw entries should appear
openclaw "reply with the single word: ready"
```

Then confirm the call in Triw **Logs**.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Provider missing | `models.providers` placed in the wrong file | Use `~/.openclaw/config.json5`, or `~/.openclaw/agents/<id>/models.json` |
| Agent answers from another provider | `agents.defaults.model.primary` not set to `triw/...` | Set the primary model |
| `401` | `${TRIW_API_KEY}` unresolved | Export the variable, or inline the key |
| Tool loop stalls | Model without tool support | Use a coding model |
